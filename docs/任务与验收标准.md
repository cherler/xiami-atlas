# 任务与验收标准

> 配套 `产品落地规划.md`。那份定「做什么、什么顺序」，这份定「**具体做哪几步、做到什么程度算完**」。
>
> **验收分三类**，每条任务都标了：
> - `[自动]` —— `scripts/validate.mjs` 或 `scripts/verify.mjs` 能查出来，不通过就是没完成
> - `[核对]` —— 有明确清单可以逐条打勾，不需要判断
> - `[判断]` —— 需要人看一眼拍板，写清楚看什么
>
> 规矩一：**`[自动]` 那一栏必须先写进脚本，再开始做任务。** 没有检查器的验收标准等于没有。
>
> 规矩二：**自动验收会骗人，全绿只是入场券，不是通过。**
> 这一轮已经被咬过三次 —— 状态码 200 但渲染的是首页；数 DOM 元素个数但它们根本不可见；
> 页面看着完全正常却每次打开都在报 hydration 错误。**每一次都是「量错了东西却以为量对了」。**
>
> 所以每个批次收尾必须再走一遍**对抗性复查**，换角度问：
>
> 1. **这条检查能不能在功能坏掉的情况下照样通过？** 能，就说明它量的不是那件事
> 2. **同一件事换一个角度量，结论一样吗？**（查内容 vs 查状态码；量可见性 vs 数 DOM）
> 3. **我是不是在检查我写的东西，而不是用户会遇到的东西？**（构建产物 vs dev server；桌面 vs 手机；首屏 vs 滚到底）
> 4. **有没有沉默的失败？**（抓不到、超时、空内容 —— 它们不会喊）
> 5. **拿一条已知是错的数据喂进去，检查器会不会响？** 不响就是摆设

# 批次 A · 地基

## A1 动线落地

### A1-1 写 `data/flows.json`
把三条动线变成数据，页面从它渲染出口，**而不是每页手写「下一步」链接**。

```jsonc
{
  "flows": [
    { "id": "pick", "name": "我要做一件事，用谁？",
      "steps": [
        { "page": "/",         "q": "你想做什么",       "exits": ["/compare", "/model/*"] },
        { "page": "/compare",  "q": "这两个选哪个",     "exits": ["/where"] },
        { "page": "/where",    "q": "去哪用、多少钱",   "exits": [] }
      ] },
    { "id": "status", "name": "这东西现在到什么程度了？", "steps": [...] },
    { "id": "track",  "name": "我在追踪这个领域",       "steps": [...] }
  ]
}
```

**验收**
- `[自动]` 校验 R41：`flows` 里出现的每个 `page` 都在路由表内存在
- `[自动]` 校验 R42：除末步外，每一步 `exits` 非空
- `[核对]` 三条动线齐全，每条 ≥3 步

### A1-2 导航组件 `components/Nav.tsx`
全站共用一条导航。

**验收**
- `[自动]` verify 新增：**每个页面都渲染出可见的 Nav**（用 `getClientRects` 量，不数 DOM）
- `[自动]` verify 新增：从任意页出发，**≤2 次点击可达三条动线的起点**（用 Nav 里的链接做图搜索）
- `[核对]` 移动端 390 宽下 Nav 不换行成两行以上、不横向滚动

### A1-3 每页页脚「接下来」区块
从 `flows.json` 渲染当前页在各条动线里的出口。

**验收**
- `[自动]` verify 新增：**除末步页外，每页至少有一个指向动线下一步的可见链接**
- `[判断]` 出口文案是「问题」不是「页面名」——写「多少钱、去哪用 →」不写「前往 where 页」

## A2 数据结构（先立结构，不填数据）

原则：**结构和校验先行，数据后填。** 结构定错了，填进去的数据全要返工。

### A2-1 `skills` 实体
```jsonc
{ "id": "motion", "zh": "动作复刻", "en": "Motion Control",
  "cap": "motion",                      // 关联能力轴，可空
  "io": { "in": ["人物图 ×1", "驱动视频 ≤10s"], "out": "视频" },
  "native": ["kling", "vidu-q"],        // 原生实现（模型 id）
  "opensource": [{ "name": "Wan2.2-Animate", "url": "...", "src": "...", "quote": "..." }],
  "platform_feature": [{ "p": "higgsfield", "name": "AI Dance", "discloses": "no" }],
  "limits": ["幅度大/转身多的驱动素材易崩"],
  "cases": ["AI 舞蹈", "动漫角色动画"],
  "src": "...", "quote": "...", "verified_at": "2026-08-08" }
```

**验收**
- `[自动]` 校验 R43：`cap` 非空时必须在能力轴内；`native` 里的模型 id 必须存在
- `[自动]` 校验 R44：`opensource` / `platform_feature` 每条必须有 `src` + `quote`
- `[自动]` 校验 R45：`limits` 为空时报警告 —— **一个没有「已知限制」的 Skill 页是在卖广告**

### A2-2 `change_events` 实体
```jsonc
{ "date": "2026-06-17", "entity": "kling", "kind": "pricing",
  "before": "1080P 有声 ¥1.2/秒", "after": "Turbo 档 1080P 有声 ¥1.0/秒",
  "why": "把有声拉进了和无声同价区间",
  "affects": ["skill:lipsync"], "src": "kling-price", "quote": "..." }
```

**验收**
- `[自动]` 校验 R46：`before` / `after` / `why` 三者缺一即错 —— **只有 after 的那是新闻，不是 Change Event**
- `[自动]` 校验 R47：`affects` 里的 id 必须解析得到（skill / capability / model）
- `[自动]` 校验 R48：`src` + `quote` 必填

### A2-3 `toolkit` 实体
```jsonc
{ "task": "知道哪个模型更强", "site": "Artificial Analysis", "url": "...",
  "verdict": "量的是画质偏好，不是能力",
  "caveat": "没有公开使用条款，引用可以，别整站搬",   // 负面结论，必填
  "checked_at": "2026-08-08" }
```

**验收**
- `[自动]` 校验 R49：`verdict` 和 `caveat` 都必填 —— **只有链接没有判断的就是 hao123**（§16）
- `[核对]` ≥7 条，覆盖 §16 列的七类任务

### A2-4 `effect` 效果
```jsonc
{ "m": "kling", "kind": "third-party" | "vendor-claim",
  "who": "Artificial Analysis", "value": "视频榜第 3", "url": "...",
  "quote": "...", "as_of": "2026-08-08" }
```

**验收**
- `[自动]` 校验 R50：`who` 必填 —— **我们不打分，只转述并标明是谁说的**
- `[自动]` 校验 R51：`kind=third-party` 时 `url` 必须能回源

### A2-5 `discount` 从 note 结构化出来
```jsonc
{ "p": "klingai-api", "m": "kling", "rule": "买 ≥30000 积分", "off": "9 折", "src": "...", "quote": "..." }
```

**验收**
- `[自动]` 校验 R52：`src` + `quote` 必填
- `[核对]` 现有埋在 `pricing.note` 里的折扣全部搬出来，note 里不再重复

### A2-6 `availability` 补 5 个字段
`access_type`（api/web/both）· `region` · `plan`（free/paid/trial）· `valid_from` · `valid_to`

**验收**
- `[自动]` 校验 R53：`access_type` / `plan` 取值合法
- `[自动]` 校验 R54：`valid_to` 早于今天时，`status` 必须是 `gone`
- `[核对]` 13 条现有记录全部补齐（拿不到的写 `unknown`，**不许猜**）

### A2-7 类型与校验先落地
**验收**
- `[自动]` `npx tsc --noEmit` 通过
- `[自动]` 五个新实体都是空数组时，`validate.mjs` 照样通过（不能因为没数据就报错）
- `[自动]` 每个新实体塞 1 条**故意写错的**样例，校验必须报出对应规则号 —— **验规则本身有没有用**

# 通用验收（每个任务都要过）

写进 `scripts/verify.mjs`，**不通过就是没做完**：

1. `[自动]` 数据有来源 —— `validate.mjs` 零错误
2. `[自动]` 控制台无报错 —— 含 hydration 这类「看着正常但在报错」的
3. `[自动]` 不横向滚动 —— 桌面 + 手机两个视口
4. `[自动]` 前端不放旁白 —— **单页中文字符数超过阈值即失败**（首页 ≤500，其余页 ≤800）
5. `[判断]` 删掉正文仍看得懂
6. `[自动]` 改了数据就重出分享图 —— `package.sh` 已串好

**第 4 条是这一版新加的**：把「不放旁白」变成一个能自动查的数，
否则它只是一句口号，下次又会悄悄涨回去。
