# 任务清单

> 依据：`AI_VIDEO_ATLAS_HANDOFF_V1.md` §59（修订记录）+ §60（竞品核查）。
> 最后更新：2026-08-07

## 读这份清单前，先看懂三件事

**一、阶段 0 的六周里，80% 的任务是「写字」不是「写代码」。**
这不是拖延，是 §59.4.a 的结论：这个项目唯一会致死的风险不是技术做不出来，
是**做出来之后没人愿意一直维护它**。那个风险必须在写代码之前测掉，
因为它只需要六周就能测出来，而先建站的版本要三个月才知道同一件事。

**二、§59.3 的「每周 3 小时」是稳态运营预算，不是建设期预算。**
两笔账不要混：

| | 预算 | 花在哪 |
|---|---|---|
| **建设期**（阶段 0~3） | 你正常的工作时间 | 下面这张表 |
| **稳态**（上线后，永远） | **每周 ≤ 3 小时**（硬上限） | 60% 写周报 / 30% 扫黄色队列 / 10% 实测 |

阶段 2 的全部意义，就是把稳态压进 3 小时。**如果阶段 2 做完还压不进去，项目该停。**

**三、每个阶段末尾都有一个 go / no-go，而且判据是分发不是产品。**
沉没成本是这类项目最常见的死法（原 §51 已经警告过）。判据写在下面，别改。

## 阶段 0 · 六周耐力测试（不写代码）

**唯一目标：证明"能一直做"和"有人看"。**
这一阶段结束前，**一行 Postgres、一个 CMS、一个 ETL 框架都不要碰**。

### B 组 · 周报（主线，第 1~6 周）

这是阶段 0 的**主线任务**，也是将来稳态里占 60% 时间的那件事。

| # | 任务 | 产出 | 完成判据 | 估时 |
|---|---|---|---|---|
| **B1** | 建初始 Source 清单 | `sources.md`，30~50 条 | 每条标注：官方/独立/社区、有无 API、有无 RSS | 0.5 天 |
| **B2** | 写第 1 期周报 | 一篇 + `changes/2026-W33.json` | 按 §15 的 `Change + So What` 结构 | 1 天 |

> **两条纪律**：
> 1. **每期必须同时产出结构化 JSON。** 写周报就是在录数据 —— 这是阶段 1 的全部数据来源。
>    只写文章不写 JSON，等于六周白干。
> 2. **耗时曲线本身就是判据。** 如果第 6 期还要一整天，说明这活儿压不进 3 小时，
>    答案已经出来了，不必等到阶段 2。

### C 组 · 数据格式（第 2~3 周，穿插做）

只做到"能让周报沉淀下来"的程度，**不要做全 Ontology**。

| # | 任务 | 产出 | 完成判据 | 估时 |

> **C2 的 `by` 字段现在就要有。** 它是 §59.3「机器录入 / 人工核验」标记的地基，
> 后补的话所有历史数据都没有来源身份。
> **C1 的 `summary` 一律写成 `summary_i18n: { zh: ... }`**（§59.2，现在多写三个字段，将来省一个季度）。

## 持续性工作（不是任务，是习惯）

上线后永远存在，总计每周 ≤ 3 小时：

- **写周报**（60%，约 1.8h）—— 这是分发，是唯一的增长动作
- **扫黄色队列**（30%，约 0.9h）—— ≤20 条，只处理看着不对的，看着对的一律放过
- **实测一两条**（10%，约 0.3h）

> **警戒信号**：某周变成 80% 在修数据 → 绿色通道太窄了，该放手（触发 F6）。

## 明确不做（守住范围）

阶段 0~3 全程不碰。任何"顺手加一下"的提议都应被否决：

- ❌ Postgres / Payload / Directus —— 阶段 2 结束前一律 git + JSON
- ❌ Neo4j —— 数据量根本不到（原 §57.1）
- ❌ RAG / 聊天机器人 —— 原 §41、§13
- ❌ Benchmark、画质评分 —— Artificial Analysis 已占死（§60.2③）
- ❌ AI Image / Audio / Agent / Robotics —— 守住 AI Video（§55）
- ❌ 全站 i18n 框架 —— 只有三个编辑字段是多语言（§59.2）
- ❌ 下载别人 Demo 重新托管 —— 大陆托管让侵权后果更直接（§59.2）
- ❌ 公司 → 团队 → 模型的组织树主图 —— 那是红海（§60.2④）
- ❌ 任何"需要人工逐条审核"的新环节（§59.3）

## 三条最容易走偏的地方

1. **阶段 0 忍不住开始写代码。** 六周里最难的不是写周报，是看着 §59.5 的清单
   觉得"先把站搭起来也不费事"。搭了就会开始调样式，周报就断了。
2. **周报只写文章不写 JSON。** 当期省 20 分钟，阶段 1 直接无米下锅。
3. **阶段 2 做完 F1~F7 就宣布成功。** 唯一验收是 F8 那个数字，不是功能清单。
