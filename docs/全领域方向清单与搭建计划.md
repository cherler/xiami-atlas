# 全领域 AI 能力地图：方向清单与搭建计划

> 项目叫 **AI 能力地图**，AI 视频是**第一个方向**，不是全部。
> 本文列出与「AI 视频模型能力地图」**同一层级**的其余方向，以及怎么一个个搭起来。
>
> 主方案 `AI_VIDEO_ATLAS_HANDOFF_V1.md` §62 已把数据结构改成多方向可扩：
> `models.domain` + `capabilities.domain` + 校验 R26 拦跨方向格子。
> **加一个方向 = 改数据，不改代码。** 本文讲的是改哪些数据、按什么顺序。

---

## 一、什么算「同一层级的一个方向」

判断标准只有一条，是 Ontology 规则二往上推一层：

> **一个方向 = 一组模型，它们的能力放在同一根轴上比较才有意义；
> 而这根轴换到别的方向就没有意义。**

检验：「首尾帧」对文本模型没有意义，「上下文长度」对视频模型没有意义
→ 视频和文本是两个方向。✓

「文生图」和「图生图」共用一根轴（都是图像生成的输入形态）
→ 它们是同一个方向里的两项能力，不是两个方向。✓

**不算方向的东西**（会把地图撑烂，明确排除）：
- AI 应用 / 产品（Futurepedia 收的那类）—— 我们收**模型**，产品进 `platforms`
- Agent 框架、推理引擎、向量库 —— 是工具链，不是能力可比的模型
- 「多模态」不是一个方向 —— 它是若干方向的交集，按输出物归到对应方向

## 三、共享层 vs 每个方向自己的层

这决定了第二个方向要花多少钱。

### 一次建好、所有方向复用（**已经有了**）

| 层 | 现状 |
|---|---|
| `orgs` 公司实体（含总部经纬度、投资关系） | ✅ 已建 |
| `platforms` + `availability` 去哪用 | ✅ 已建 |
| `pricing`（平台 × 模型 × 档位） | ✅ 已建 |
| `sources` + 采集流水线（watch/extract/triage/三色通道） | ✅ 已建，62 个源 |
| `versions` 版本谱系 | ✅ 已建 |
| 校验框架（R0~R40） | ✅ 已建 |
| 前端骨架、分享图、SEO、纠错入口 | ✅ 已建 |

### 每个方向必须自己做

| 层 | 为什么不能复用 |
|---|---|
| **capabilities 能力轴** | 定义就是「这根轴换个方向就没意义」 |
| **Ontology 规则**：收谁不收谁、什么叫「支持」、别名表 | 每个方向的门槛不一样 |
| **models + support 格子** | 逐格核验，跑不掉 |
| **skills** | 「动作复刻」和「工具调用」不是一类东西 |
| **该方向特有的数据源** | LLM 有 LMArena，视频没有；图像有 Artificial Analysis 的另一榜 |

**结论：方向 1 花的大头是基础设施，方向 2 起主要成本是 ontology + 首批采集。**

## 四、跨方向才有的价值 —— 这才是做全领域的理由

**不是做 10 张互不相干的地图，是同一批公司在 10 个方向上的全景。**

这个价值已经有硬证据，而且数据现在就在我们手里 ——
挖视频版本谱系时，这批条目被我当成「别家」过滤掉了，
**它们不是别家，是同一家公司的其他方向**：

```
字节 Seed（来自 seed-blog 快照）
  Seedance     视频
  Seedream     图像
  Seed Audio   语音
  Seed3D       3D
  SeedRealtime 世界模型 / 实时
  Seed-2.1     大语言模型
  Seed GR      具身智能

MiniMax（来自官方 Hugging Face 组织）
  MiniMax-H3           视频
  MiniMax-M1/M2/M3     大语言模型
  MiniMax Speech 2.8   语音
  MiniMax Music 3.0    音乐
```

由此能回答的问题，**别处一个都拼不出来**：

1. **一家公司押了哪几个方向、哪个先出、哪个停了** —— 公司页的「全方向时间线」
2. **哪些能力在跨方向迁移** —— 「角色一致」从图像走到视频再走到 3D，是同一件事在三个方向的落地
3. **同一个平台上，一家公司的模型是不是配套齐了** —— 火山方舟上字节的视频/图像/语音是否都能调
4. **一个工作流要串几个方向** —— 出图 → 生视频 → 配音 → 配乐，每一步用谁、总共多少钱
5. **国别与方向的分布** —— 中国厂商集中在视频和图像，美国厂商集中在语言和具身，这是可验证的事实

第 4 条最有产品价值：**用户真正的任务从来不落在单个方向里。**

## 五、每个方向的启动清单（模板）

每个方向按同一套流程走，一条不能跳 —— 视频这一轮跳过 C1 的代价是 36% 的格子错了。

```
D-1  写方向的 Inclusion Policy：什么模型收、什么不收，写下三条判据
D-2  定能力轴：8~12 项，每项写清「什么叫支持」，并列出各家别名
D-3  定 Core 名单：≤10 个 Family（规则四），其余进 extended
D-4  找数据源：官方文档 / changelog / 官方 HF 组织 / 官方价格页，登记进 sources.json
D-5  逐格核验：只认厂商官方，每格带来源与原文，不许用自己的词去搜（规则六的教训）
D-6  接共享层：orgs / platforms / availability / pricing / versions
D-7  过校验：R26 拦跨方向格子；核对 Core ≤10、yes 必须有 src
D-8  上前端：方向切换器加一条，页面代码不动
D-9  补四个公共页：/caveats /changes /toolkit /basics（内容 + 快捷导航）
```

**D-2 是唯一不能压缩的一步。** 能力轴定错，后面每一格都白核。

### D-9 是 2026-08-13 补的一步 —— 因为它被忘了三次

负责人原话：「上面的几个公共页（toolkit / changes / basics）要记住：
后续添加新的 AI 工具方向（AI 3D、具身智能、世界模型？）的**跨方向导航与内容**，
要在做具体方向时一起更新。」

做完一卷自己的现在页 / 演进树 / 场景页，人会很自然地以为收工了。
08-11 那次图像卷在 /caveats 上是空的、文本卷在三页上全是空的，都是这么来的。

**所以这一步不靠记性，靠两条会挂的检查：**

- `validate.mjs` 的 **R68**：四个公共页每个上线方向都要有内容，
  否则报错；确实没有的要在 `domains[].gaps` 写明理由。
  /basics 的覆盖看 `glossary.tutorials[].domains` —— ⚠️ **通用基础课标空数组、不计入**，
  否则「有一门通用课」就能让新方向自动过关。
- `verify.mjs` 的**方向筛选条**：在浏览器里数 /changes 与 /toolkit 的筛选按钮，
  必须覆盖所有 `state: "live"` 的方向。数据对了但组件没接上，静态校验看不出来。

## 六、排期

约束（负责人锁定）：**人力每周 ≤3 小时**，宁可不精准也要 Agent 自主。

| 阶段 | 内容 | 判据 |
|---|---|---|
| 现在 | **AI 视频做完整**（前端落地方案 V1 的 10 步） | 五条验收全过，且有真实读者反馈 |
| 下一个 | **AI 图像** | 理由见下 |
| 再下一个 | **大语言模型** 或 **AI 语音**，看反馈 | |
| 之后 | 按第一/二/三梯队顺序，每次只开一个 | |

### 为什么第二个方向选 AI 图像

1. **能力轴与视频最接近**（角色一致、风格参考、局部重绘都是同源概念），
   规则六的别名表能直接复用一半 —— **这是最省的一次 ontology**
2. **厂商高度重叠**：字节、阿里、Google 在两个方向都有，
   `orgs` 与 `platforms` 几乎零新增，**第一次跨方向视图立刻就能出**
3. **用户任务天然连着**：出图 → 生视频是最常见的一条链，
   立刻能兑现第四节第 4 条的价值

### 明确不做的事

- **不同时开两个方向。** 每个方向的 ⬜ 都要靠人工核验收口，
  两个方向一起开会把每周 3 小时直接击穿。
- **不为了凑数收方向。** 第三梯队的定义还在变，
  现在建 ontology，半年后要重建 —— 那是负债不是资产。
- **不在方向没做完时改名。** 站上现在写「AI 视频能力地图」是诚实的；
  等第二个方向上线再改成「AI 能力地图」。

## 七、另一条轴：专项系列（2026-08-13 负责人提出，**只登记，还没展开**）

> 原话：「我其实想做一个专项系列：比如 AI 做游戏、AI 做视频。
> 上面的几个工具方向都是以**模型**为区分，这个专项我想以具体的**落地应用**。
> 你先记一下，后续再具体展开。」

### 它和「方向」不是一回事

现有的四卷（视频 / 图像 / 文本 / 声音）是按**模型能不能放在同一根轴上比**来切的 ——
这是第一节那条判据。专项系列切的是另一刀：

| | 工具方向（现有） | 专项系列（新的一条轴） |
|---|---|---|
| 切分依据 | 模型的能力轴 | 要做成的那件事 |
| 一个条目长什么样 | 「AI 图像」= 一组可比的模型 | 「AI 做游戏」= 从想法到成品的一条链 |
| 回答的问题 | 这一类模型谁强、强在哪 | 我要做这件事，该按什么顺序用哪些东西 |
| 天然是 | 横切（一个模型进一卷） | 纵切（一条链会横穿四卷） |

「AI 做游戏」会同时用到图像（美术）、声音（配音与 BGM）、文本（剧情与代码）——
**它不是第五个方向，硬塞进 `domains` 会把方向那条判据搞坏。**

### 展开前要先定的三件事（等负责人拍板）

1. **和现有 `applications` 什么关系。** 场景页已经有 30 个应用（短剧、海报、配音…），
   那已经是「按落地应用切」的东西了。专项是**把若干应用串成一条链**，
   还是另起一套实体？串起来的话，数据上可能只是 `series` + 有序的 `applications` 引用。
2. **可核验的是什么。** 这一站所有内容都有「来源 + 原文 + 核验日期」这条命。
   一条制作链里「先做什么再做什么」很容易变成我们自己的主张 ——
   **那就破了整站的规矩**。得先想清楚哪部分有官方出处，哪部分只能标成「我们的做法」。
3. **先做哪一条。** 「AI 做视频」和现有视频卷重叠最多、最容易验证形态；
   「AI 做游戏」跨度最大、最能证明这条轴的价值。两者选一个先试，不要一起开
   —— 和第六节「不同时开两个方向」同一条纪律。

### 2026-08-14 补：第三个专题「AI 做 Agent」，以及 Agent 到底指什么

负责人原话：「可以具体到应用专题：比如前面提到的 AI 做游戏、AI 做视频、**AI 做 Agent**，
对吧。Agent 也不单指代码，还有**工作类、自动化类**等等，开源的 openclaw、hermes 都算。」

这一条同时解决了两个悬着的问题：

**一、「代码 Agent」为什么不是方向，但「AI 做 Agent」是专题。**
它俩切的不是同一刀。代码 Agent 想进 `domains`，靠的是「它是一类可比的模型」——
不成立，它的产出物是文本，轴在文本卷里。而「AI 做 Agent」是**一条要做成的事**，
纵切、横穿几卷，正是专题这条轴的形状。

**二、Agent 的范围不是「写代码的那种」。** 按落地形态至少三类，实测样本：

| 形态 | 实例（2026-08-14 实测） | 星 | 许可 |
|---|---|---|---|
| **运行时 / 外壳**（自己接模型、装插件） | `deepseek-ai/deepseek-harness`（`dsh`，TypeScript，跑在 Cordis 上，插件化到「模型适配器与 agent loop 本身都是插件」） | 80,701 | MIT |
| **个人助理**（跨平台、常驻） | `openclaw/openclaw` | 386,258 | ⚠️ **NOASSERTION** |
| **Agent 本体**（带记忆、会长大） | `NousResearch/hermes-agent` | 230,356 | MIT |

⚠️ **openclaw 的许可是 NOASSERTION** —— GitHub 认不出它用的是哪一种。
在这个站上说一个东西「开源」而不提这件事，就是我们自己犯了整天在别人身上挑的毛病
（工具箱里 `hello-agents` 那条踩过同一个坑）。

**三、它们进不了任何一卷，这不是遗漏。** 第一节的排除项写着「Agent 框架、推理引擎、
向量库 —— 是工具链，不是能力可比的模型」。`dsh` 的产出物是**跑起来的任务**，
不是视频 / 图 / 音频 / 3D 资产 / 动作序列里的任何一种。**没有归属地不等于该硬塞一个。**

> 仍然只登记。§七 那三件要拍板的事（与 `applications` 的关系、哪部分可核验、先做哪一条）
> 一件都没定，`dsh` / openclaw / hermes 现在**不进 `atlas.json`**。
