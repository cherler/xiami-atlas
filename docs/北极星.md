## 一、最高验收标准（原话，不许抽象掉）

理想的用户反馈**不是**：

> “这个网站好酷。”

**而是**：

> “靠，我终于搞懂 Kling、Seedance、Higgsfield 到底是什么关系了。”

—— `方案讨论` 第四轮结尾

这句是全部判断的原点。HANDOFF §7.1 把它抽象成了「删掉正文仍能看懂」——
**抽象之后「搞懂关系」被降权成了一条排版规则，这是法典最大的失真。**
凡是让人「看懂一张表」但没让人「搞懂一层关系」的页面，都没达到这条标准。

判据：读者离开时能不能补上一句「原来 X 和 Y 是这种关系」。补不上，这页就没达标。

## 二、产品是什么：连接四个平行世界

互联网上有四套互不连接的平行世界：

| 世界 | 谁在做 | 现状 |
|---|---|---|
| 1 · 模型 | Seedance、Kling、Veo、Wan… | Artificial Analysis 做得强，但只有排名 |
| 2 · 运行平台 | Replicate、fal、火山、百炼… | 只列模型，不讲关系 |
| 3 · 商业应用 | Higgsfield、CapCut、Pika… | **不告诉你背后是什么模型** |
| 4 · Skill / Workflow | Motion Control、ComfyUI workflow… | 最乱，无人整理 |

> **这四个世界之间缺连接。这就是我们做的地方。**

所以产品不回答「什么是 Seedance」，而回答：

> **Seedance 在整个 AI 生态里处于什么位置，我能拿它干什么？**

名字定为 **AI 能力地图 / AI Atlas** —— 是**地图**不是**百科**。
地图的本体是**边**（谁属于谁、谁基于谁、谁在哪用），不是**点**（一个个词条）。

---

## 三、三张图，就是全部主线

用户只要三个问题的答案。导航就是这三个词，其余一切都是它们的下级或废案。

| 图 | 回答 | 数据基础 | 状态（2026-08-09） |
|---|---|---|---|
| **现在** | AI 视频研发到哪一步了？谁能做什么？ | Entity + Capability（点，已扎实） | ✅ 首页真值表已达标 |
| **演变** | 谁在什么时候长出了什么？解决了上一代什么问题？ | versions（时间线，已扎实） | ✅ 演化树已达标 |
| **关系** | 谁是谁家的？谁基于谁？谁在哪用？ | **Relation（边，几乎是空的）** | ❌ **真正的洞** |

「演变」的原始意图（`方案讨论` 第七节）不是版本流水，是**能力演化**：
> Text-to-Video → Image-to-Video → Reference → First/Last Frame → Character Ref → Motion Control → Multi-shot → Native Audio → Unified Editing
> 点一个节点看「它解决了上一代什么问题」。
这比「Seedance 2.0 排名第一」有价值得多。

## 四、为什么「关系」这么难 —— 因为缺的是边，不是图

架构四层（前端 / 知识 / 研究 / 采集）里，最空的一格**不是前端，是知识层的 Relation**：

| 边 | 现有 | 可得性 |
|---|---|---|
| 模型 ↔ 平台（在哪用） | 13 | 平台文档公开，最易采 |
| 模型 ↔ 模型（基于谁） | **0** | 仅开源侧可查，论文/模型卡里写着「基于 XX」 |
| 公司 ↔ 地点（总部） | 5/15 | 官网 about 页，一轮清完 |
| 公司 ↔ 公司（投资） | 5 | 上市公司招股书 S 级，其余多半查不到 |

Entity 和 Capability 都是点，**没有边它就是三张列表，不是地图**。
产品叫地图，缺的恰恰是让它成为地图的那一层。**「关系」这张图做不出，不是画不出，是没数据可画。**

## 五、被否的废案（连同理由，别再回头提）

`方案讨论` 里已经否掉、有明确理由、不要再走的路：

| 废案 | 否定理由 |
|---|---|
| 叫「AI 百科 / Wiki」 | 已有人做且认真做，真空白在**关系**不在词条 |
| 上 Neo4j / 图数据库 | 第一阶段用不上；git-diff 当审核机制严格胜过它 |
| Cytoscape / 复杂 Network Graph | 会糊成蜘蛛网；先分层图，节点上几十再说 |
| LLM confidence 字段 | 伪精度，去掉；信不信由来源等级和人工核验定 |
| 现在就做「全部 AI」 | 先把 AI 视频一个方向做深做透，再扩 |
| 「做好前端 = 成功基石」 | 修正为「做好**认知体验** = 基石，前端只是它的表达工具」 |

## 六、开发节奏（`方案讨论` 定的，我违反过）

> 不要先做全套漂亮前端，也不要先造大 Agent。
> **先做两个极小原型，各自跑通，再连起来。**
> - 前端原型：手工 JSON 的一张漂亮图，验证视觉体验
> - 数据原型：只研究 Seedance + Kling，跑通 Source→Fetch→Snapshot→Diff→Extract→Claim→Evidence→Review→Fact

我违反过这条：一口气铺了 13 页。教训——**每次只推进一张图，且图与数据同时推进**，不要再摊大摊子。

## 七、这一页怎么用

- 想**加一页**：先问「它服务三张图里的哪一张？不服务就不加。」
- 想**砍一页**：先问「砍了之后，三张图还完整吗？完整就砍。」
- 想**改一版**：先问「离『搞懂关系』更近还是更远？更远就退回。」
- 想**争一个大方向**：先查第五节废案表，理由多半已经在那儿。

法典（HANDOFF）继续管执行细节：建某页、查某规则、界定收不收某模型。
但**方向永远回到这一页**。
